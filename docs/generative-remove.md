# Local AI Remove

PhotoCraft extends the existing Remove tool with optional local Rust inference. Desktop and CLI builds include LaMa and MI-GAN CPU support by default; model weights are installed separately. OSOR-SDXL Phase II is an additional opt-in native adapter for object removal that can include shadows and reflections. Builds without a learned backend, and the browser build, keep Classical Remove.

## Use the tool

1. Select Remove from the J-tool flyout and open **Models…** in its options bar (also Edit → Preferences → Generative Remove Models).
2. For LaMa or MI-GAN, download a model or choose **Install from file…** for its exact catalog artifact. The catalog pins its source revision, expected size and SHA-256. A renamed or incompatible ONNX file is rejected. For OSOR, choose **Install from folder…** and select a prepared local bundle as described below; PhotoCraft does not download or convert OSOR weights.
3. Enable local AI removal, enable the desired process, and select its model. Installation and enabling processing are separate choices.
4. Choose **AI** in the Method control and paint over the object. Processing starts on release, or collect strokes with Remove after each stroke off and press Enter. With OSOR, review the completed canvas preview and choose **Apply** (Enter) or **Cancel** (Esc). **Shadows and reflections** allows OSOR to change the bounded surrounding context as well as the painted hole, within the current selection. With that option off, edits stay inside the painted hole. LaMa and MI-GAN remain hole-only.
5. Esc also cancels pending strokes or cancellable work. **Create a new layer** leaves the source layer unchanged; applying a completed repair is one undo step. A ready preview changes neither the document nor its history.

**Classical** preserves the existing algorithm. Existing commands without `method` also retain that behavior. **Auto** reports its effective method and fallback reason; it currently uses Classical because no learned model has passed the separate broad quality and performance gates for automatic selection. Explicit AI errors never silently retry Classical. A brush stroke never downloads a model.

| Model | Optional download | Runtime |
| --- | ---: | --- |
| LaMa | 208,044,816 bytes (208 MB) | Native Rust tract CPU, fixed 512×512 model context |
| MI-GAN v1 | 29,546,882 bytes (30 MB) | Native Rust tract CPU, exact older MI-GAN pipeline |
| OSOR-SDXL Phase II (`osor-sdxl`) | Local converted bundle; no PhotoCraft download | Opt-in osor-rs CPU/F32, or explicit Metal/F32 on macOS; up to 512 px context |

The manager exposes the model source, license, expected hash and installation/readiness state. It offers download, cancellation, import and removal. Downloads use HTTPS, bounded streams, staged writes and hash verification. The catalog lists OSOR even when its adapter was not compiled; each model reports its own runtime availability. Models remain offline after installation. A running noninterruptible forward can continue draining after logical cancellation, while its resource permit remains held.

## Supported editing contexts

The learned bridge accepts full-colour RGB U8/U16 raster targets in sRGB, with opaque known context. It preserves the document depth and uses fractional selection coverage once at final write. It can fill a transparent hole from opaque context and can write a new layer. HDR/32f, other colour models/profiles, channel/mask targets and complex masked/clipped/effect layer arrangements receive a compatibility error for explicit AI. Sample All Layers currently accepts only simple raster composites. Classical remains available for other contexts.

The operation captures the source, target, selection, brush geometry, model and settings before work begins. The active gesture freezes its effective brush at pointer-down, so later brush changes cannot alter its tinted footprint. Queued UI strokes are discarded when their context changes, including a change and restoration within one action. Oversized rendered footprints are rejected before coverage allocation; the bound includes soft-tip tails, sampled-tip rotation, and scattering. Busy gestures are refused before capture, so a press during processing cannot become a later accidental stroke.

Small repairs read bounded source regions rather than resize the document. The model input pads the crop while preserving aspect ratio; oversized crops are explicitly scaled and the command result reports `inferenceScale` and the crop bounds. OSOR downsamples only above a 512 px long side, pads to multiples of eight (at least 32 px), and restores RGB and predicted edit alpha to the source crop dimensions. Its RGB already contains latent-space alpha blending; the predicted alpha is not multiplied into that RGB again. The service permits one model operation at a time and caches one model family. Preflight also caps the combined generated brush work at 262,144 estimated dabs, including scattering and dual tips. Live and queued tint use the same check before rendering. Admission includes spare capacity for generated dabs, walker steps and smoothing buffers as well as the model working-set estimate and a conservative pixel-buffer bound against the captured Preferences → Performance → Memory Usage value before allocating crop buffers. OSOR admission uses a conservative 40 GiB model working-set estimate plus transient buffers. Bundle headers are bounded to 12 GiB of decoded F32 weights, and the native loader enforces that bound on the actual hashed input before tensor allocation. For native evaluation, set Memory Usage to 49,152 MiB (`performance.memoryUsageMb`) to allow headroom for transients; the default budget can reject OSOR before allocation. This estimate is not an operating-system RSS cap.

A preview retains the exact completed candidate and its resource admission until Apply or Cancel; applying it does not run inference again. Source, target, selection, document, working-profile or relevant settings changes invalidate it. A stale or mismatched preview cannot be applied. Effects previews require explicit review and are unavailable during action or script playback; ordinary LaMa/MI-GAN action playback is unchanged.

## Local OSOR bundle

Prepare a bundle using the offline converter from [osor-rs](../crates/ml/README.md#osor-sdxl-phase-ii-bridge). The selected directory must contain `manifest.json`, `unet.safetensors`, `vae.safetensors` and `prompt.safetensors`: the SDXL Inpainting base, Phase II adapters merged into the UNet, five-channel output head, VAE and cached fixed-prompt embeddings. A generic SDXL checkpoint or LoRA file alone is insufficient.

Import validates the manifest and hashes all four files, then stores a small reference receipt in the managed model directory. It neither copies the multi-GB weights nor downloads anything. Keep the source directory at its imported path without symlinks; the files are reverified before inference, including warm inference. Import verification does not establish that the neural graph loads or that its output is qualified. Moving or modifying the bundle makes the reference unavailable. **Remove model** deletes only the reference and warm cache, leaving the source bundle untouched. Remove the current reference before importing a different bundle.

The [upstream OSOR model card](https://huggingface.co/QinmingZhou/OSOR#license) identifies the SDXL weights as **CreativeML Open RAIL++-M**, including use restrictions. The Rust library uses MIT; that code license does not replace the weights or base-model licenses. Obtain, convert, use and redistribute weights only under their applicable terms. PhotoCraft ships no OSOR weights and grants no additional model rights.

## Storage and builds

Models use machine-local app data: Application Support on macOS, LOCALAPPDATA on Windows, and XDG_DATA_HOME (or `~/.local/share`) on Linux. `PHOTOCRAFT_CONFIG_DIR` keeps models beneath that override. Portable mode uses `PhotoCraftData/models` beside the executable and does not silently redirect an unwritable model folder. `PHOTOCRAFT_MODEL_DIR` explicitly selects another real, writable directory, including Scratch during development. Weights and download partials are never embedded in the binary or committed to this repository.

`cargo build -p photocraft` and `cargo build -p photocraft-cli` enable `local-ai` for the ONNX adapters; use `--no-default-features` to omit that backend. Add `--features osor` for CPU/F32 OSOR or, on macOS, `--features osor-metal` to explicitly select Metal/F32 in the native app and CLI. These features can also be combined with `--no-default-features`. `photocraft-ml` itself has no default inference feature. The OSOR dependency currently uses the live development checkout `/Users/justin/Workspaces/0xdoublesharp/osor-rs`; a portable immutable source pin remains pending. Default compilation and tests need no model files, and normal tests never download weights. Put build outputs and temporary files on Scratch as required by `AGENTS.md`.

Trusted local CLI run/batch/droplet entry points restore only the saved Generative Remove choices and memory budget from the normal preferences file, using the same portable-directory writability and fallback policy as the desktop; remote automation receives no such file read or implicit processing opt-in. Batch scratch sessions retain that same budget. Corrupt owned model files remain removable in the manager before reinstalling.

Engine clients share `paint.remove` with `method: classical|auto|ai` and optional `modelId`, `remove.capabilities`, and `ai.models.list`. For explicit review, pass `preview: true`; `removeEffects: true` requires that flag and the `osor-sdxl` model. Inspect with `remove.preview.status {}`, then use `remove.preview.apply {id?}` or `remove.preview.discard {id?}`. Passing the returned candidate ID binds the action to that exact preview. Explicit local model administration uses `ai.models.install`, `ai.models.import` and `ai.models.remove`; OSOR import takes the bundle directory as `path`. Untrusted automation and action/script playback cannot install, import or remove models. The command registry documents parameters and background-job results.

## Qualification and further work

Native LaMa and MI-GAN have matching-artifact numerical checks on a supplied 512×512 scene within one decoded byte value, and real installed-model apply/undo coverage on macOS. The native development app was also exercised through its control channel: the model manager and queued tint were visually inspected, a queued stroke completed real MI-GAN inference, and Undo restored the exact original PNG export. Its isolated model was imported and removed through the native CLI. Those checks do not establish Photoshop parity or broad image quality. Linux/Windows runtime behavior, signed packaging, native download-button/file-dialog journeys, wider quality categories and learned browser execution require their own qualification. PhotoCraft native OSOR/Metal testing on macOS now covers a verified local bundle, queued-stroke effects preview, unchanged source export before Apply, exact PNG restoration after Undo, warm preview discard, cancellation with worker drain and clean exit. These are bounded application checks on a synthetic scene, separate from broad removal quality, Photoshop parity, packaged builds and other native platforms.

The release `generative_remove_bench` validates a small repair in a dense 6000×4000 procedural cloud/noise image on an Apple M2 Max (12 logical CPUs, 96 GiB RAM). It reports cold and warm runs, the captured context crop, loading/forward time and sampled whole-process RSS. Runs during the shared compilation window are co-located validation, not calibrated performance budgets or broad image-quality qualification. The example uses already installed catalog artifacts and never downloads weights.

OSOR-SDXL Phase II is available only in builds with its opt-in adapter and an explicitly imported local bundle. The adapter contract and qualification limits are recorded in [the ML README](../crates/ml/README.md). Moebius has no adapter. No external Python/model server is used by the Remove inference path. Prompted Generative Fill/Expand is separate work.

The development integration currently consumes the local `osor-rs` checkout; the tested source is commit `0263f15c9ddd0067f7224c686330e0d6e308fca6`. A portable Git dependency requires the library owner to publish a shared remote. The local path is intentional while the library is being tested alongside PhotoCraft.
